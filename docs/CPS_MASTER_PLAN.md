## 0. المنتج في صفحة واحدة

- **ماذا:** منصة SaaS متعددة المستأجرين تبدأ كبرنامج فواتير وسندات بسيط وتنمو إلى ERP كامل — محاسبة وخزينة ومخزون ومشتريات وأصول وموارد بشرية وتشغيل قطاعي — بواجهة عربية أولًا بلغة كل مهنة.
- **لمن:** الشركات الصغيرة والمتوسطة في **السعودية والخليج أولًا ثم مصر** (سوق ثانٍ رسمي)، من المكتب الخدمي بموظف واحد إلى المجموعة القابضة.
- **لماذا نحن (التموضع):** «شمول دفترة بضوابط مراقب مالي» — دورة اعتماد وفصل واجبات، مرفقات كدليل إثبات ببصمة رقمية، قيود مرحّلة محمية على مستوى قاعدة البيانات، شركات قابضة وفروع بتقارير مجمّعة، وكل رقم يُتتبَّع حتى مستنده.
- **الاسم والهوية:** CPS (اختصار Cloud Path Solutions) — الشعار: سحابة سماوية `#45A9D9` فوق حروف كحلية `#3A5286`؛ الدومين **`cps-erp.com`** (الموقع `www`، التطبيق `app`، كل شركة على `<slug>.app.cps-erp.com`).
- **الحجم المستهدف:** 12 قطاعًا و54 نشاطًا (ما تعرضه دفترة) عبر نواة واحدة + ≈ 10 وحدات رأسية + طبقة تهيئة «حزمة النشاط» — لا 54 منتجًا.
- **أين نحن:** سبرنتات 0 → 4.8 مكتملة (229+ اختبارًا آليًا على Postgres حقيقي)، المحاسبة الفعلية مبنية، سبرنت 5 قيد التنفيذ، نسخ احتياطي يومي مختبَر.
- **الزمن:** النواة حتى سبرنت 12 ≈ 4–5 أشهر؛ القطاعات (13 → 26) ≈ 7–8 أشهر إضافية؛ التسويق القطاعي يبدأ بعد 7.5 لا في النهاية.

### 9.2 دورة السبرنت (ثابتة)
1. نقاش → تحديث الوثائق (سجل القرارات في `SYSTEM_ANALYSIS.md` عبر تعليمات لـ Claude Code؛ الوثائق الأخرى مباشرة).
2. المعماري يكتب `docs/prompts/sprint-<n>.md` (كتل مرقّمة، اختبارات، معايير قبول، commit لكل كتلة، قواعد ثابتة).
3. المالك يرفع الملف بـ Xftp ويكتب في Claude Code: `نفّذ docs/prompts/sprint-<n>.md`.
4. Claude Code ينفّذ كتلةً كتلة، يسأل عند أي قرار غير موثّق، يعرض أي migration تلمس بيانات قبل تشغيلها (بعد `scripts/backup.sh`)، ويكتب `docs/sprints/<n>-summary.md`.
5. بعد آخر commit: `docker compose restart backend celery_worker` → `make smoke`.
6. المعماري يراجع الملخص → ملاحظات/تصحيح (`<n>.8`) عند اللزوم.
7. UAT بشري بسكربت `docs/UAT/sprint-<n>.md` ← `docs/UAT_LOG.md`.
8. تحديث الكتالوج (حالة الوحدات) والوثائق، ثم فتح السبرنت التالي.

### 9.3 تعريف الإنجاز لكل سبرنت
كل الاختبارات السابقة والجديدة تعدّي على Postgres حقيقي · `ruff` نظيف · `next build` بلا أخطاء · الاختبار البنيوي للعزل يعبر · commit لكل كتلة بالاسم المتفق · الملخص مكتوب بما لم يكتمل ولماذا · restart + smoke · UAT بشري موثّق (للسبرنتات المحاسبية) · الكتالوج وسجل القرارات محدَّثان · **مطابقة الخطة والهوية (من 6.0.1):** `check-brand` (لا لون خارج `tokens.css`، تباين AA) و`check-money` (كل مبلغ عبر `Money`) والمسح العربي للرسائل يمرّون، وقسم «المطابقة» في ملخص السبرنت يذكر أي انحراف عن 3.18 · **تقرير مطابقة كامل** (`docs/reviews/PLAN_COMPLIANCE_<n>.md`) مع كل مراجعة معمارية · **الكتل التي تلمس الواجهة (من 6.5.8):** `make e2e` يمرّ — تحقّق حقيقي بمتصفح Playwright headless على مستأجر `smoke-*` جديد عبر الشاشة الفعلية (لا نداء API مباشر)، `frontend/e2e/*.spec.ts`، لقطات الشاشة في `docs/uat/screens/<n>/`.
