# UAT سبرنت 4 — الدليل الشجري ومحرك القيود والمحاسبة الفعلية

**الهدف:** محاسب حقيقي (لا مطوّر) يمر بهذه الخطوات على بيئة التطوير
(`http://<subdomain>.localhost:3000` أو الرابط المكافئ) بحساب Owner أو
Accountant، ويسجّل النتيجة الفعلية (✅/❌ + ملاحظة) في العمود الأخير —
أو في `docs/UAT_LOG.md` إن أراد تفصيلًا أطول لأي خطوة. أي "❌" يُوقف
إغلاق السبرنت حتى يُحل أو يُوثَّق كديْن تقني صريح في README.

**قبل البدء:** مستأجر تجريبي جديد (أو مستأجر Acme الحالي)، بنوع نشاط
"تجارية" (trading) عند التسجيل إن أمكن — لإتاحة قالب دليل حسابات أوسع
في الخطوة 1.

| # | الخطوة | المتوقَّع | النتيجة |
|---|---|---|---|
| 1 | افتح **المحاسبة ← دليل الحسابات**. تحقق من وجود شجرة حسابات كاملة (نقدية/بنوك/عملاء/موردون/موظفون/إيرادات/مصروفات/ضريبة) منذ التسجيل، بدون أي خطوة إعداد يدوية. | شجرة تظهر فورًا بحسابات نظام مُعلَّمة (لا تحتاج إنشاءها يدويًا). |  |
| 2 | من نفس الشاشة: اضغط "إضافة حساب فرعي" تحت أي حساب مصروفات، أضف حسابًا جديدًا بكود واسم عربي. | الحساب الجديد يظهر فورًا في الشجرة تحت أبيه الصحيح. |  |
| 3 | حاول تعديل نوع حساب له قيود مُرحَّلة عليه (مثال: حساب النقدية بعد أي فاتورة). | تُرفض العملية بخطأ واضح — لا يُسمح بتغيير نوع/أب حساب عليه سطور. |  |
| 4 | افتح **المحاسبة ← أكواد الضريبة**. تحقق من وجود أكواد الضريبة السعودية الستة (قياسي 15%، صفري، معفى، خارج النطاق، احتساب عكسي، غير قابل للخصم) مبذورة تلقائيًا. | 6 أكواد موجودة، القياسي بنسبة 15%. |  |
| 5 | افتح **المبيعات ← الفواتير**، أنشئ فاتورة بثلاثة بنود: بند بكود ضريبة "قياسي" (S)، بند بكود "صفري" (Z)، بند بكود "معفى" (E)، كل بند بمبلغ مختلف. | الإجمالي يحسب ضريبة 15% على بند S فقط؛ Z وE بلا ضريبة. |  |
| 6 | اعتمد الفاتورة من الخطوة 5، ثم افتح القيد الناتج (من **المحاسبة ← القيود اليدوية** أو **التقارير ← ميزان المراجعة**). | سطر ضريبة واحد فقط في القيد (لا سطر لكل بند)، بمبلغ ضريبة بند S فقط؛ القيد متوازن (مدين = دائن). |  |
| 7 | أنشئ فاتورة جديدة بعملة مختلفة عن عملة الكيان الأساسية (مثال: USD على كيان أساسه SAR) — افتح "العملة وسعر الصرف" ولاحظ التعبئة التلقائية لسعر الصرف. | السعر يُعبَّأ تلقائيًا من آخر سعر مُسجَّل؛ يمكن تجاوزه يدويًا. |  |
| 8 | افتح **الخزينة ← أسعار الصرف**، أضف سعرًا جديدًا لنفس زوج العملات بتاريخ اليوم. أنشئ فاتورة أخرى بنفس العملة، تحقق أنها تستخدم السعر الجديد لا القديم. | الفاتورة الجديدة تعتمد أحدث سعر بتاريخ ≤ تاريخ الفاتورة. |  |
| 9 | افتح **الإعدادات ← قواعد الاعتماد**، أضف قاعدة: نوع المستند "قيد يدوي"، الحد الأدنى للمبلغ 10,000، الدور المطلوب "المالك". | القاعدة تُحفظ وتظهر في القائمة. |  |
| 10 | بحساب محاسب (ليس مالكًا)، افتح **المحاسبة ← القيود اليدوية**، أنشئ قيدًا يدويًا بمبلغ 20,000 (سطرين متوازنين)، ثم أرسله للاعتماد. حاول اعتماده بنفس الحساب. | الإرسال ينجح (يصبح "بانتظار الاعتماد")؛ محاولة الاعتماد بنفس حساب المحاسب تُرفض (403) — المنشئ لا يعتمد لنفسه. |  |
| 11 | سجّل دخول بحساب **المالك**، افتح **صندوق الاعتماد** (الشريط الجانبي — لاحظ العدّاد). اعتمد القيد من الخطوة 10. | القيد يظهر في الصندوق بالمبلغ والوصف الصحيحين؛ بعد الاعتماد يختفي من الصندوق ويصبح قابلاً للترحيل. |  |
| 12 | من **المحاسبة ← القيود اليدوية**، رحّل القيد المعتمد من الخطوة 11. | حالة القيد تصبح "مرحّلة" (شارة خضراء)، ويظهر أثره في ميزان المراجعة. |  |
| 13 | أنشئ 6 قيود يدوية إضافية متنوعة (مبالغ وحسابات مختلفة، بعضها بعملة أجنبية من الخطوة 7-8) وأكمل دورة الاعتماد/الترحيل لكل منها — إجمالي 10 قيود يدوية منذ بداية هذا الاختبار (الخطوة 10 + هذه الـ6 + 3 قيود إضافية حرة الاختيار). | كل قيد يُنشأ ويُرسل ويُعتمد ويُرحَّل بنجاح دون خطأ غير متوقَّع. |  |
| 14 | افتح **المحاسبة ← القيود اليدوية**، اختر أحد القيود المرحّلة (من الخطوة 12 أو 13)، اضغط "عكس القيد" واكتب سببًا. | يُنشأ قيد عكسي جديد "مرحّل" فورًا؛ القيد الأصلي تتغير حالته إلى "معكوسة" لكنه يبقى ظاهرًا في القوائم والتقارير (لا يُحذف ولا يُخفى). |  |
| 15 | افتح **التقارير ← ميزان المراجعة**. تحقق من إجمالي المدين = إجمالي الدائن، وأن القيد المعكوس من الخطوة 14 صفّر أثره (الحساب المتأثر عاد لرصيده قبل ذلك القيد). | إجمالي مدين = إجمالي دائن دائمًا؛ الرصيد بعد العكس صحيح. |  |
| 16 | افتح **الإعدادات ← ترقيم المستندات**، غيّر بادئة نوع مستند "فاتورة" إلى بادئة مختلفة، احفظ، ثم أنشئ فاتورة جديدة. | الفاتورة الجديدة تحمل البادئة الجديدة؛ الفواتير القديمة تبقى بأرقامها الأصلية دون تغيير. |  |
| 17 | (إن كان للمستأجر أكثر من فرع نشط) قارن رقمي أول فاتورة صدرت من فرعين مختلفين. | الرقمان مختلفان (يتضمنان كود الفرع) رغم أن كلًا منهما "أول فاتورة" لفرعه. |  |
| 18 | افتح **المحاسبة ← فترات الإقرار**. تحقق من وجود فترات مُولَّدة تلقائيًا للسنة الحالية بلا أي إعداد يدوي. | قائمة فترات (شهرية أو ربع سنوية حسب إعداد الكيان) تظهر تلقائيًا، حالتها "مفتوحة". |  |

**ملخص القبول:** السبرنت يُعتبر مقبولًا من منظور المحاسب فقط إذا كانت
كل الصفوف أعلاه ✅. أي ❌ يُنسخ كديْن تقني صريح في قسم "ديون تقنية" في
`README.md` مع رقم الخطوة، أو يُصحَّح فورًا إن كان بسيطًا، قبل اعتبار
سبرنت 4 مغلقًا فعليًا.
