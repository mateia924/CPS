# UAT سبرنت 5.5 — التسوية البنكية، جرد الصندوق، اعتماد تغيير IBAN

**الهدف:** محاسب حقيقي (لا مطوّر) يمر بهذه الخطوات على بيئة التطوير
(`http://<subdomain>.localhost:3000` أو الرابط المكافئ) بحساب Owner أو
Accountant، ويسجّل النتيجة الفعلية (✅/❌ + ملاحظة) في العمود الأخير —
أو في `docs/UAT_LOG.md` إن أراد تفصيلًا أطول لأي خطوة. أي "❌" يُوقف
إغلاق السبرنت حتى يُحل أو يُوثَّق كديْن تقني صريح في README.

**قبل البدء:** مستأجر به بنك وصندوق نقدية مسجَّلان برصيد حقيقي (سند قبض
سابق)، مورد واحد على الأقل، ومستخدمان فعّالان على الأقل (Owner
ومحاسب) لاختبار فصل الواجبات في طلب تغيير IBAN — مستأجر بمستخدم واحد
لا يختبر هذا الفصل (استثناء 3.15.1 متعمَّد).

**ملاحظة منهجية:** هذا السكربت لم يُنفَّذ عبر API مسبقًا في هذه الدورة
— عمود "النتيجة" أدناه فارغ عمدًا بانتظار محاسب بشري فعلي، انظر
`docs/UAT_LOG.md`.

| # | الخطوة | المتوقَّع | النتيجة |
|---|---|---|---|
| 1 | من تفاصيل البنك، تبويب "التسوية"، اضغط "استيراد كشف". اختر CSV، عبّئ التخطيط (عمود التاريخ/المبلغ/البيان) بما يطابق ملفًا تجريبيًا يحوي حركة بنفس مبلغ وتاريخ سند قبض مُرحَّل سابقًا لهذا البنك، وحركة أخرى بلا نظير في الدفاتر. | الاستيراد ينجح؛ الحركة الأولى تُطابَق تلقائيًا (شارة "تلقائي")؛ الثانية تبقى "غير مطابَقة". | |
| 2 | من نفس التبويب، افتح سطر الكشف غير المطابَق، اضغط "مطابقة" ثم "مطابقة المحدد" بلا اختيار سند (توقَّع رفضًا)، ثم اضغط "تجاهل" بلا سبب (توقَّع رفضًا)، ثم كرّر بسبب. | المطابقة بلا اختيار تُرفض؛ التجاهل بلا سبب يُرفض (400)؛ التجاهل بسبب ينجح وتتحول حالة السطر إلى "متجاهَل". | |
| 3 | أنشئ سند قبض بمبلغ 1,000 وسند صرف (رسوم بنكية) بمبلغ 15 لنفس البنك بنفس التاريخ تقريبًا، رحّلهما. استورد كشفًا يحوي حركة واحدة بمبلغ 985 لنفس التاريخ. افتح سطر الكشف، اختر السندين معًا، اضغط "مطابقة المحدد". | السطر يتحول "مطابَق" رغم أنه سندان منفصلان (مطابقة مجمّعة). محاولة مطابقته بسند واحد فقط (1,000 وحده) تُرفض قبل ذلك برسالة "المجموع لا يطابق". | |
| 4 | افتح "تقرير التسوية" أعلى تبويب "التسوية" لنفس البنك. | الفرق النهائي صفر (أو قيمته الصحيحة إن بقيت حركات معلّقة عمدًا)؛ القوائم الأربع (إيداعات في الطريق/مدفوعات معلّقة/بنود لم تُقيَّد/بنود متجاهَلة) تعكس ما فعلته في الخطوات 1–3. | |
| 5 | من تفاصيل صندوق نقدية له رصيد حقيقي، تبويب "الجرد"، اضغط "عدّ جديد" وأدخل مبلغًا مختلفًا عن الرصيد الدفتري المعروض. أكّد بلا سبب (توقَّع رفضًا)، ثم أكّد بسبب مع تفعيل "إنشاء سند تسوية". | التأكيد بلا سبب يُرفض؛ بسبب ينجح، يحمل رقمًا يبدأ بـ CC، وسند التسوية الناتج (قبض أو صرف حسب الزيادة/العجز) يُرحَّل فورًا؛ رصيد الصندوق الدفتري بعده يطابق المبلغ المعدود. | |
| 6 | من تفاصيل مورد (أو بنك)، اطلب "تغيير IBAN" بقيمة جديدة وسبب، لكن حاول الإرسال للاعتماد **قبل** رفع خطاب IBAN. | الإرسال يُرفض (400) لغياب المرفق الإلزامي. | |
| 7 | ارفع خطاب IBAN كمرفق على الطلب، أرسله للاعتماد. بنفس حساب المحاسب الذي أنشأ الطلب، حاول اعتماده. | الحالة تصبح "بانتظار الاعتماد"؛ محاولة الاعتماد الذاتي تُرفض (403). | |
| 8 | بحساب Owner، اعتمد الطلب من الإعدادات ← "طلبات تغيير IBAN" (أو صندوق الاعتماد الموحّد). افتح تفاصيل المورد/البنك بعدها. | IBAN تغيَّر فعليًا للقيمة الجديدة؛ محاولة تعديله مباشرة من فورم المورد/البنك بقيمة أخرى تُرفض (400) وتوجّه لشاشة الطلبات. | |
| 9 | حاول إنشاء سند صرف لمورد له طلب تغيير IBAN آخر بحالة "بانتظار الاعتماد" (أنشئ طلبًا ثانيًا بلا اعتماده). | إنشاء/ترحيل السند يُرفض (409) لحين حسم طلب IBAN المعلّق. | |
| 10 | من "دفتر الأستاذ" (التقارير)، افتح حساب البنك المستخدَم أعلاه بفلتر "غير مسوّاة فقط" إن وُجد، وقارن برصيد تقرير التسوية من الخطوة 4. | السطور المعروضة تطابق قائمة "إيداعات في الطريق/مدفوعات معلّقة" في التقرير بالضبط. | |
| 11 | افتح **التقارير ← ميزان المراجعة** بعد كل الخطوات أعلاه. | إجمالي المدين = إجمالي الدائن (سند التسوية من الخطوة 5 لم يكسر التوازن). | |
