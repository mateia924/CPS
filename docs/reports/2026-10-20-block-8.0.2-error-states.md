# Block 8.0.2: named error states; a list never renders a failure as empty (2026-10-20)

Owner's order: fix in the shared layer.

- 404, JSON 500 and HTML 500 each render a named error state.
- A list must NEVER render an error as an empty result.

The serious case was live on the day of writing: an HTML 500 on a list read "لا توجد بيانات لعرضها". That tells
an accountant there are zero records when the server failed. Not deployed yet.

## What changed

| Where | Change |
|---|---|
| `frontend/src/components/ScreenErrors.tsx` (replaces 8.0.1's `ScreenAccess.tsx`) | `apiErrorKind()`: 403 -> forbidden, 404 -> not-found, >=500 -> server-error, 0 -> network. `<ErrorState>` renders the named state (`data-state=...`). `<ScreenErrors>` in the dashboard layout turns any ApiError no screen handled into that state. |
| `frontend/src/components/DataTable.tsx` | A failed load clears the rows (no stale page left looking like the answer) and renders `<ErrorState>` in the table instead of the empty message. A failure with no named kind (e.g. a 400 on a filter) shows as server-error, never as empty. |
| `frontend/src/app/not-found.tsx` (new) | Unknown route: the app's own Arabic not-found state, instead of Next's English "404 This page could not be found". |
| Five lists that are not DataTable: approvals inbox (+ emergency tab), attachments panel, change history, incoming transfers, profile sessions | Each showed its own "nothing here" text after a failed load. Each now shows the named state. The attachments badge shows "(!)" instead of "(0)". |
| i18n | `errorNotFound*`, `errorServer*`, `errorNetwork*`, `errorPageNotFound`, `errorBackToDashboard` (ar/en). The server-error text says outright that what is on screen is not the result and does not mean there are no records. |

Audit of the other custom lists (`grep "length === 0"`):

- The dashboard, customer/employee detail tabs, reconciliation dashboard and bank-reconciliation candidates
  render nothing at all when their own load fails, and the shell then names the failure. None of them claims
  an empty result.
- Asset additions/disposals/transfers come from the asset record itself, not a separate load.
